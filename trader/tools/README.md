# trader/tools — durable ops scripts (survive container resets)
All order scripts append an INV-12 intent line to trader/orders.jsonl and print the ref_id to use.
- `hb.py "<note>" HH:MM[et]` — loop sleep to a UTC time (or ET with the `et` suffix, DST-safe), capped at 480s per call.
- `bridge.py HH:MM:SS[et]` — exact-time sleep (UTC, or ET with `et`), refuses legs >= 500s. After 2026-11-01 (EST) always use the `et` form.
- `exit_ovn.py NIGHT YYYYMMDD SYM:QTY:BID ... [--reprice] [--dry]` — §5 09:31 exit limits (bid − max(0.02, 0.15%); `--reprice`: bid − 0.3%). QTY may be the broker's quantity string (3.000000, 3.997642): the whole-share part is sold here and the tool prints the `exit_frac.py` command for any remainder. A quantity of 0 is skipped. An exit is never refused for a log reason.
- `entry_v16.py nvdl NIGHT YYYYMMDD NVDL_ask NVDL_last E [--dry]` then `entry_v16.py nvdx NIGHT YYYYMMDD NVDX_ask NVDX_last E SPENT [--dry]` — §3 v1.6 NVDL-first sizing (entry_v15.py kept for history only).
- `trend.py add YYYY-MM-DD QQQ=.. NVDA=.. SMH=.. [--force]` (07:45, prior session's official closes) and `trend.py state QQQ=<px> NVDA=<px> SMH=<px> --log` (15:50; 12:50 on a half-day) — §13 market-trend state (v1.8, no orders). QQQ binds: UP -> f 0.98, DOWN -> f 0.25. **Exit code 2 = no valid state**: the cache is short, stale (its last close is not the previous NYSE session), has a missing or a non-session date in the 199-close window, or the tool crashed. Follow the printed repair and re-run; if that is not possible before the entry, size DOWN. A problem with NVDA or SMH (shadows) never changes the QQQ result. Other commands: `show` (cache, missing and non-session dates), `del YYYY-MM-DD [SYM ...]` (remove a mistyped date), `closed YYYY-MM-DD [--remove]` (declare an unscheduled full-day market closure; stored in `research/trend/closed.json`), `init BARS.json ...` (rebuild from day bars of ALL symbols; needed after a stock split). `add` refuses weekends, holidays, today or later, a different value for a cached date and a move over 25%; a bad value for one symbol does not block the others. The log keeps the read that sized the order: a re-run replaces a date's rows only on the same day within 20 minutes. The NYSE holiday table inside the tool ends 2028-12-31.
- `entry_v18.py core NIGHT YYYYMMDD NVDL_ask NVDL_last E up|down|pause [--dry] [--again]`, then `entry_v18.py topup NIGHT YYYYMMDD E SPENT up|down|pause [--dry] [--again]` — §3(c) v1.8 sizing: whole NVDL shares by limit, then one dollar-based market top-up (>= $2.00). The top-up comes after the core fill, or at once with SPENT 0 when `core` prints `x0` (one share costs more than the target; there is then no core order). PAUSE = exactly 1 share and no top-up. `entry_v18.py reprice NIGHT YYYYMMDD NVDL_ask NVDL_last E STATE` is the §4 15:55 step (cancel the first order first; limit = ask + 0.3%, at most last × 1.0055). Hard stops, never overridden: unknown flag, bad number, E <= 50, limit above the cap. Log checks (a second intent of the same kind, a top-up that does not match the night's core intent or its state) stop the tool, print the stored intent and say when `--again` is right; `--again` overrides only those. Under `--dry` they print a note. A partial fill followed by a re-price has no tool path: size the remainder by hand and journal it. Supersedes entry_v16.py from night 45.
- `exit_frac.py NIGHT YYYYMMDD SYM QTY [--dry] [--again]` — §5 v1.8: market sell of the fractional remainder (0 < QTY < 1, at most 6 decimals, trailing zeros fine), after the whole-share limit sell has filled, or as the only exit order when the position is under 1 share. A second intent for the night stops the tool and prints the first; `--again` writes a new one (broker rejection, or dust left after a fill).
- `shadow_tza.py YYYY-MM-DD BARS.json` — §11 v1.7 TZA shadow log (no orders); feed it 1-minute TZA bars.
- `dayleg.py N YYYYMMDD TZA_ask TZA_last cash E [--dry]` / `daytp.py N YYYYMMDD ENTRY QTY` / `daysell.py N YYYYMMDD QTY BID [--reprice]` — §11 day leg.

## sleeve_r4.py (RULES_v3 §12(e), FFB-L options sleeve)
`python3 trader/tools/sleeve_r4.py E S EXPIRY K:bid:ask ...` applies R4 to the call quotes you pass. It prints the spread-mode pick ($10 wide, L0 = mid + 25% toward natural, cost <= B = min(0.2E, E-80), W/L0 >= 4, liquidity guard), the L2 single-call pick, and every candidate considered. Strike-to-instrument ids for the Jan-15-2027 expiry are in `trader/research/sleeve/nvda_calls_2027-01-15.json`. The same tool serves the shadow log and live orders.

## watchdog_check.py (notify-only dead-man check, added 2026-11-13)
`python3 trader/tools/watchdog_check.py [--final]` reads only git objects of the trading branch (`FETCH_HEAD` after a fetch): the newest commit time and `trader/state.json`. It prints QUIET, ALERT or BLIND and never writes, pushes or touches the broker. It is run by the scheduled task `t3x-watchdog` in a fresh session with no connectors. If a field it reads is renamed (`today.date`, `exit_done`, `eod_done`, `positions[].entry_t`, `positions[].leg`), update the script in the same commit.

## hbc.sh / shadow_rec.py (moved into the repo 2026-11-13)
`bash trader/tools/hbc.sh "<note>" "<commit title>" [TAG]` appends a journal line, stamps `state.wake`, commits `trader/` and pushes. `python3 trader/tools/shadow_rec.py "15:25 ET" E S "K:bid:ask ..." EXPIRY` records one options-shadow reading in `state.today.sleeve_shadow`.

## Cadence commitment (human-confirmed 8/14)
Platform floor is 1-minute scheduling with 1-10 min delivery latency; 30-second wakes are not schedulable. Deployment runs the platform maximum where it matters: IN_POSITION -> chained 1-minute wakes; FLAT -> boundary-aligned checkpoint wakes (entries only occur at checkpoints, so denser polling adds nothing while flat). GTC broker-side stops provide real-time downside protection between wakes.

## Standing wake schedule (human-confirmed 8/14, "most frequent where it makes sense")
- FLAT in RTH: one-shot wake at EVERY decision boundary (5-min S1 closes when armed; :00/:30 S2 checkpoints; 15:00 trail; 15:30 S3; 15:50 carry; 16:10 EOD) + the 30-min cron backstops. The Analyst wake schedules that day's full boundary set each morning.
- IN_POSITION: chained 1-minute wakes (platform floor) for synthetic stop/ratchet/halt checks; GTC native stop rests broker-side between wakes.
- Off-hours flat: fast path (no scheduled wakes beyond Analyst + crons). Holding overnight: 15-min monitoring one-shots.

## Ops lessons (living section; updated 2026-08-19 after 4 sessions, 3 trades)
1. IN-TURN BRIDGING IS PRIMARY, one-shots are the entry point: a single wake bridges an entire window (arm + S1 closes; a whole position lifecycle; the close-out 15:30->16:10) via python sleep chunks. Rules: chunk <= 560s with Bash timeout=600000 (590s chunks got backgrounded twice — recoverable but noisy); always sleep-to-absolute-target, never fixed durations; after any backgrounded sleep, re-read the clock and re-target.
2. DUPLICATE-WAKE FAST PATH: on wake, read clock first. If state.json heartbeat is recent, no boundary is due before the next armed one-shot, and mode is FLAT with no open orders -> reply NOOP and end the turn with zero further tool calls. (~15 duplicates/day arrive by design; they are the redundancy, not a bug.)
3. VWAP ACCUMULATOR: persist today.vwap_acc = {SYM: {pv, vol, asof_utc}} in state.json at every checkpoint that computes VWAP ((h+l+c)/3*v cumulative). Each later checkpoint fetches only bars after asof_utc. Eliminates full-session recomputation and transcription risk. (Adopted from session 5.)
4. ANALYST PRE-COMPUTES ABSOLUTE LEVELS: store U_B dollar levels per checkpoint (not just multipliers) in state.today at plan time, keyed off max(open,PC) once the open prints (arm wake updates them). Checkpoint eval then = one bar fetch + one comparison.
5. CLOSE-OUT SCHEDULING TRIMMED: schedule 15:26 (bridges 15:30->16:10 in one turn) + 15:46 backstop only; drop the 16:06 one-shot — the 16:00Z-hour cron already backstops EOD. Saves 1-2 duplicate wakes/day with no coverage loss.
6. EXIT LADDER CONFIRMED GOOD: marketable limit at bid - max($0.02, 0.0015P); if unfilled 60-90s on a sliding bid, cancel -> re-price once. Both live exits filled with price improvement; 8/18's two-attempt exit beat the eventual close.
